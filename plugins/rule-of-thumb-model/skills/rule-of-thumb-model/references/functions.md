# Function catalogue

Generated from `scripts/lib/functions.py`. After editing the catalogue there, run `python -P -X utf8 -B scripts/lib/functions.py --write` from the skill folder. The audit and the build read the catalogue in the code, not this file.

- Functions in the catalogue: 172 (34 refused, 39 flagged, 99 allowed in profile `both`).
- The nesting depth of a formula counts every function call, whatever its class (design 8.1).

## How the classes are used

| Class | Rule | Severity | Effect |
| --- | --- | --- | --- |
| refused | F-FUNC-REFUSED | error | `build` refuses the specification (exit 2); `audit` reports an error. |
| flagged | F-FUNC-FLAGGED | warning | `--strict` exits 1. A model accepts named flagged functions with `settings.allow_functions` in its specification. |
| allowed | - | - | no finding |
| not in the catalogue | F-FUNC-UNKNOWN | warning | check that the function exists in both products |

- Volatile functions (TODAY, NOW, RAND, RANDBETWEEN, RANDARRAY, CELL, INFO) are reported as F-VOLATILE (warning). A flagged volatile function is reported once, as F-VOLATILE, not also as F-FUNC-FLAGGED.
- OFFSET and INDIRECT are volatile too; they are reported only as F-FUNC-REFUSED (design 14).
- `settings.allow_functions` silences F-FUNC-FLAGGED and F-VOLATILE for the functions it names. It does not change a refused function.

## Profiles

- `both` (the default): the workbook must work in Excel and in Google Sheets.
- `excel` and `sheets`: a function that is restricted only because the other product lacks it is allowed in its own product (design 8.5). A function that does not exist in the profile's product is refused there. A class that rests on modelling practice (FAST, the books) stays the same in every profile.
- The profile is the specification's `product` key, or `--product` on `audit`, `compat` and `formula`.
- A model that uses a function only Google Sheets has (JOIN, SPLIT, REGEXMATCH and the others this catalogue marks Excel "no") cannot be verified in Excel: build prints I-SHEETS-ONLY, and `rotm.py check` reports X-SHEETS-ONLY, does not open the workbook in Excel, leaves the file byte for byte and exits 3 ("audited, not recalculated: functions only Google Sheets has"). Prefer the alternative the catalogue names (for JOIN the & operator). Such a model is listed under "Not verified".
- The functions only Google Sheets has (Excel `no`, Sheets `yes`): QUERY, ARRAYFORMULA, IMPORTRANGE, IMPORTDATA, IMPORTHTML, IMPORTXML, IMPORTFEED, GOOGLEFINANCE, SPARKLINE, SPLIT, JOIN, REGEXMATCH.

## Evidence labels

- "confirmed": the claim was checked against its source in `research/verify/` (the id names the item, for example platforms A3.6 or local guides L-96).
- "not confirmed": the claim is stated in a research report but was not re-checked there, or it is the builder's reading of the Microsoft and Google function lists.
- Excel column: `yes` = in Excel 2010 or later (the availability text names a later first version where one applies); `365` = needs a recent Excel (the Excel versions column lists the versions that have it); `no` = not in Excel.
- Excel versions column: the versions that have the function, newest first. `rotm.py compat` writes its advice about Excel versions from this list (for example LAMBDA: Microsoft 365 and Excel 2024, not Excel 2021). The source of each list is in the availability column.
- Sheets column: `yes`, `no`, or `not confirmed` (no evidence that Google Sheets has it).

## The Lift column

- `yes`: the Python script that `rotm.py lift` writes reproduces the function. The column is generated from `lib.lift.supported_functions()`, the one list the lift evaluator keeps.
- `no`: `rotm.py lift` reports `LIFT-UNSUPPORTED` (error, exit 1) for a model that uses the function, before the script is written, with the number of cells and the first cell. The script shows those cells as not reproduced.
- Lift reproduces 90 of the 172 functions in the catalogue.
- PROPER: a word is a run of letters by Unicode, as Excel 16 treats it (measured on the code points up to U+3FFFF); a text with a character the script lists as not reproduced (2,239 measured characters whose case Excel gives otherwise, for example U+00B5, U+0130 and U+03A3, and the code points not measured) is not reproduced.
- ROW: only ROW() without an argument, on a helper sheet.
- TEXT: only the formats yyyy, yy, mmmm, mmm, mm, m, dddd, ddd, dd, d (dates), 0, 0.0, #,##0, #,##0.00, 0%, 0.0%, General and @.
- Lift also reproduces these functions, which are not in the catalogue (a model that uses one gets F-FUNC-UNKNOWN): ISNONTEXT, LOG, LOG10, PI, QUOTIENT.

## Functions that differ between the products

- A function in this list exists in Excel and in Google Sheets under the same name, but takes other arguments in one of them. Its class does not change; `rotm.py compat` reports the cases that differ.
- FILTER: differs between the products in its third argument: in Excel the third argument of FILTER is the value returned when no row matches (Microsoft's FILTER page: FILTER returns an error on an empty result unless its third argument is given, platforms A3.7, not confirmed); in Google Sheets FILTER takes a range and then conditions, FILTER(range, condition1, [condition2, ...]), so a third argument is a further condition (builder's reading of Google's FILTER page, not confirmed); rotm.py compat reports a FILTER with a third argument at its cell (X-FILTER, warning) and does not rewrite it.
- CONCAT: differs between the products: Excel's CONCAT takes any number of arguments and ranges; Google Sheets' CONCAT takes two values (builder's reading of the Microsoft and Google function pages, not confirmed); exactly two single values is the form both products share; rotm.py compat reports a CONCAT with one argument, with more than two arguments or with a range argument (X-CONCAT, warning), and rewrites it with & when every argument is a single value (one argument a becomes a&"", the same text).

## The file prefixes `_xlfn.`, `_xlfn._xlws.` and `_xlpm.`

- Excel stores a function added after Excel 2007 with the prefix `_xlfn.` in the file, FILTER and SORT with `_xlfn._xlws.`, and the names that LET and LAMBDA define with `_xlpm.`. A spill reference `A1#` is stored as `_xlfn.ANCHORARRAY(A1)` and the `@` operator as `_xlfn.SINGLE(...)`; the formula rules show it as `@<argument>` (`@(<argument>)` for an expression) and do not count it in the nesting depth.
- openpyxl writes the formula text it is given. `build` passes every formula through `formula.to_file_formula()`, which adds these prefixes (design 6.6).
- `formula.analyze()` and the audit work on the text the formula bar shows: `formula.strip_xlfn()` removes the prefixes first, so a stored `_xlfn.ANCHORARRAY(A1)` is measured as `A1#` (depth 0), not as a function call.
- The list of prefixed functions is the builder's reading of the Excel file format (not confirmed by `research/verify/`).
- Verified in Excel 16.0 on the build PC on 2026-11-25 (test `test_file_prefixes_recalculate_in_excel` in `scripts/tests/test_formula.py`): 11 formulas written by openpyxl in the form `to_file_formula()` gives (XLOOKUP, XMATCH, MAXIFS, IFNA, CONCAT, IFS, LET, LAMBDA, MAP with LAMBDA, FILTER and SORT) recalculated to the expected values, and `=XLOOKUP(...)` written without the prefix showed `#NAME?`.
- Not verified: the other prefixed functions; whether Excel also accepts LET and LAMBDA names without `_xlpm.`; spill references and `@` written by openpyxl. The Excel test runs only where Excel is available.

## Volatile functions

- FMD p306 lists OFFSET, INDIRECT, RAND, NOW, TODAY, ROW and COLUMN as volatile (books B-56, confirmed).
- The plugin does not treat ROW and COLUMN as volatile: Microsoft's list of volatile functions does not include them (builder's reading, not confirmed), and helper columns use `=ROW()` (design D8).
- RANDBETWEEN, RANDARRAY, CELL and INFO are volatile in Microsoft's list (builder's reading, not confirmed).

## Choices for Max

- IFERROR, IFNA and ISERROR are allowed (design 8.5). The research synthesis (D10) proposes flagging IFERROR, IFNA, ISERROR and ISERR, because PwC lists them as lower risk and says "Always test for the specific error, e.g., ISNA" (local guides L-98, confirmed). Changing IFERROR to flagged would make every IFERROR a warning.
- RAND, RANDBETWEEN and CELL are flagged (design 8.5). The research synthesis proposes refusing them.
- NPV, IRR, XNPV and XIRR are flagged (research synthesis D10; local guides L-98, confirmed). The design did not list them; a model that reports an IRR allows it with `settings.allow_functions`.
- 48 common functions (for example MOD, INT, ROUNDUP, SUBSTITUTE, WEEKDAY, PMT) are allowed as the builder's addition to the design's allowed list. Their availability in both products is the builder's reading of the vendors' lists (not confirmed). Without them each would be an F-FUNC-UNKNOWN warning.
