# Template: starter

Starter model: expenses by category and month.

The smallest complete model: one raw table, one helper sheet, one grid, its checks and the master check. Copy it with rotm.py init --template starter and change it.

## Use it

1. `rotm.py init <new model folder> --template starter` copies this folder into a new model folder without its
   `queries/`, `raw/`, `reports/`, built workbook and manifest. The sample extract stays in `data/`. The contracts
   come back as `proposed`.
2. Show the user `contracts/lines.contract.md` and record the reply with `rotm.py contract agree <new model folder>
   --table lines --reply "<their words>" --by <name>` (SKILL.md P1).
3. After the agreement, land the sample extract (or your own extract of the same table):

   ```
   rotm.py land <new model folder> --table lines --csv <new model folder>/data/lines.csv
   ```

   Land writes `raw/lines.csv` and `queries/lines.sql` and `queries/lines.pq.m`, each stamped with the agreed contract's
   hash (P2).
4. Build, audit, check and render: `rotm.py build <new model folder> --strict`, then SKILL.md P7. Change
   `model.spec.json` for your own model first (P3 to P6).

## Raw tables (contracts)

- `lines`: one row per expense line; key line_id; columns line_id (text), line_date (date, date), category (text), amount (number, KRW).

The shipped contracts carry an agreement marked as the template's own (channel `example`, "no user gave it"); build
accepts it only inside the plugin's folders.

## Sheets

- `inputs` (inputs)
- `raw_lines` (raw): expense lines as landed (contract lines)
- `h_lines` (helpers): one row per expense line: its month end
- `calc` (calc): expenses by category and month
- `checks` (checks)

Build also writes the cover, the generated checks of every raw table (row count, control total, empty cells in
never-null columns, coverage by helper rows, repeated keys) and the master check.

## Checks written in the specification

- `spend_ties_raw`: Grid total equals the raw total of amount.

## How it was built and tested

- Data: `make_data.py` writes `data/*.csv` and `data/controls.json` (deterministic, seed 20261125). The data are
  generated, not copied from a course or book file.
- Built with `rotm.py build --strict` (exit 0) and audited with `rotm.py audit --strict` (exit 0).
- Recalculated in Excel 16.0 by `rotm.py check --strict`: checks: 9 of 9 hold; master check 0.
- Every sheet rendered to `reports/render/` and looked at.

## Limitations

- Starter template of the rule-of-thumb-model plugin: the data are generated by make_data.py (seed 20261125).
- Three months, January to March 2026.
- Inputs are changed in `model.spec.json` and the model is rebuilt. A value typed into the workbook's inputs sheet is not kept by a rebuild, and build refuses to overwrite such a file without `--force`.
